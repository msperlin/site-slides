# Site Slides

A simple, static website framework to host HTML slides for students, organized by class and chapter.

This project uses a lightweight Flask application to dynamically discover HTML presentations, which is then frozen into a static `index.html` file to be effortlessly hosted on GitHub Pages.

## Features
- **Automatic Discovery:** Automatically scans the `slides/` directory for HTML presentations.
- **Organization:** Groups slides by class and chapter, with one section per chapter and stable anchors (e.g. `#af-cap-08-avaliacao-de-acoes`).
- **Search & Filters:** Instant search over titles, chapters, filenames **and slide content**, plus class/chapter filters. The current view is stored in the URL so it can be shared.
- **Sorting:** Browse by chapter (default) or by most recently updated.
- **Freshness:** Slides changed in the last 45 days get a "Novo" badge.
- **Auto-Generated Thumbnails:** Automatically creates image thumbnails (`.png`) for each presentation using headless Chromium.
- **Static Site Generation:** Compiles the dynamic Flask app into a single, static `index.html`, plus `sitemap.xml`, `robots.txt`, `404.html` and the content search index.
- **Validation:** A link/structure checker verifies every local asset, thumbnail and search-index entry.

## Directory Structure
To add new slides, place your `.html` presentations in the `slides/` folder following this structure:
```text
slides/
└── [Class Name]/
    └── [Chapter Name]/
        └── presentation_name.html
```
*Note: Any assets, libraries, or support files (e.g., `_files`, `libs`, `resources`) generated by presentation tools like Quarto or reveal.js are safely ignored by the scanner.*

Optional companions are picked up automatically:
- `presentation_name.qmd` → used for the readable title.
- `presentation_name.png` → thumbnail (1280×720).
- `presentation_name.pdf` → PDF link.

Class and chapter display names live in `app.py` (`CLASS_LABELS` and `CHAPTER_LABELS`); new folders still work with a sensible fallback.

## Local Development & Testing

1. **Install Dependencies:**
   ```bash
   pip install -r requirements.txt
   ```

2. **Run the Flask application (Dynamic mode):**
   ```bash
   python app.py
   ```
   Open `http://127.0.0.1:5000` in your browser.

3. **Generate Thumbnails Locally:**
   ```bash
   python 01-generate_thumbnails.py
   ```
   *Requires Google Chrome or Chromium installed on your system.*

4. **Build the static site:**
   ```bash
   python 02-freeze.py
   ```
   This generates:
   - `index.html` — the frozen page served by GitHub Pages;
   - `static/search-index.json` — content index loaded on demand by the search box;
   - `sitemap.xml`, `robots.txt`, `404.html`.

5. **Validate the result:**
   ```bash
   python 03-validate.py
   ```
   Checks local links/assets, thumbnails, duplicate IDs, card/search-index consistency and required artifacts. Exits non-zero on errors.

### Site URL

`app.py` uses `SITE_URL` (default `https://msperlin.github.io/site-slides/`) for the canonical link, JSON-LD, sitemap and the 404 page. Override it when needed:

```bash
SITE_URL="https://example.com/slides/" python 02-freeze.py
```

## Deployment

The published site is the committed `index.html` (plus the generated static files) served from the repository root via GitHub Pages.

After changing slides or templates:
1. Generate thumbnails for new decks (`01-generate_thumbnails.py`).
2. Run `02-freeze.py`.
3. Run `03-validate.py`.
4. Commit the generated files and push.

The validation workflow in `.github/workflows/validate.yml` runs the build and checker on every push and pull request.
